# LLM.md — adclip project context

## Product contract

adclip is a standalone, local-first, model-routed marketing creative and
learning application. MCP is one interface adapter; it is not the architecture.

Read before architectural changes:

- `docs/README.md`
- `docs/STANDALONE_ARCHITECTURE.md`
- `docs/MODEL_PROVIDERS.md`
- `docs/MODEL_ROUTING.md`
- `docs/EMAIL_CAMPAIGNS.md`
- `docs/PERFORMANCE_LEARNING.md`
- `docs/EXPERIMENTS.md`

Binding rules:

- Core/domain/application modules must not import from `adclip.mcp`.
- CLI, MCP, and future HTTP/UI adapters call application-layer services.
- Workflows select capabilities and task routes, not vendor names.
- Route, provider, model, and generation options are separate values.
- Explicit provider/model values override route primaries.
- Provider adapters own vendor schemas; campaign and interface code do not.
- Different model families require distinct request builders. Never restore a
  universal fal request dictionary.
- Route fallbacks are visible metadata. Never silently execute another paid
  request after failure.
- Unsupported routes remain discoverable but must fail clearly until their
  required input contract and adapter exist.
- Email rendering/editing is native and send-provider-neutral. Do not put
  campaign document state inside an ESP adapter.
- Performance/experiment state belongs to adclip; platform connectors only
  retrieve or eventually deploy external state.
- Existing CLI aliases, MCP tool names, briefs, and campaign exports remain
  compatible during migration.

## Current application services

```text
AdclipApplication       creative generation, copy, routes, provider resolution
EmailApplication        email generation/render/edit/lint/export
PerformanceApplication  deployment lineage, Meta sync, reports/comparisons
```

New interfaces should call these boundaries rather than duplicating workflow

## Email campaign architecture

```text
EmailCampaignBrief
  -> provider-neutral sequence generation
  -> EmailMessage blocks
  -> HTML + text + headers
  -> lint/compliance report
  -> portable campaign bundle
```

Rules:

- `EmailMessage` block JSON is editable source state.
- Rendered HTML carries stable `adclip:block:<id>` markers.
- HTML patches target markers, not coordinate-based editing.
- The native renderer must remain usable without Node.js/MJML.
- MJML may be optional import/export/compilation support, not a mandatory runtime dependency.
- Render conservative table-based responsive HTML plus plain text.
- Reject scripts, forms, iframes, embedded objects, active media, and `javascript:` URLs.
- Marketing exports include visible unsubscribe treatment, postal-address metadata,
  `List-Unsubscribe`, and `List-Unsubscribe-Post`.
- Sender authentication, recipient-specific unsubscribe substitution, consent,
  suppression lists, and delivery belong to sending adapters.
- Rendering, linting, and patching remain local/deterministic.
- Email sequence generation uses the normal text-provider registry/runtime policy.

## Creative lineage and performance contract

Current campaign/performance state is portable JSON until SQLite becomes
authoritative.

Identity rules:

```text
campaign_id      cmp_...
variant_id       v01
creative_id      crv_...
artifact_sha256  ...
deployment_id    dep_...
observation_id   obs_...
experiment_id    exp_...
```

- `campaign_id` is stable and portable.
- When a rendered artifact exists, its SHA-256 participates in `creative_id`.
- Regenerated bytes must receive a new creative ID rather than inheriting old performance.
- Deployment records snapshot the exact local creative/artifact identity linked
  to an external ad.
- One Meta account/ad pair may not be silently relinked to a different local creative.
- Observation identity includes deployment, date window, attribution reporting
  time, and any explicit dimensions.
- Same-date observations with different `action_report_time` values must never
  be silently combined.
- Meta sync verifies both returned account ID and returned ad ID before accepting data.
- The current Meta connector is GET-only. Do not add mutation methods to the
  read-performance adapter.

## Experiment/evidence contract

A declared experiment snapshots:

- hypothesis;
- one declared changed factor;
- exact control and treatment creative IDs;
- artifact hashes when available;
- control/treatment factor values;
- primary metric and expected direction;
- design;
- minimum denominator/events per arm;
- confidence level.

Current designs:

```text
controlled_single_factor
observational_comparison
```

Rules:

- Controlled single-factor tests currently require matching formats.
- Observational comparisons are descriptive only: `inferential: false`,
  `verdict: inconclusive`.
- Current inferential rate metrics are CTR, outbound CTR, and action rate.
- CTR uses clicks / impressions.
- Outbound CTR uses outbound clicks / impressions.
- Action rate uses selected actions / clicks; do not overload it with
  actions/impressions.
- Binomial rate inference is invalid if event counts exceed the denominator.
- CPA and ROAS remain descriptive until event-level or variance-aware evidence exists.
- Minimum evidence thresholds must be met before `supported` or `contradicted`.
- Every current experiment evaluation keeps `causal_claim: false`; declared
  creative control does not prove randomized auction/audience/placement delivery.
- Next-test logic must distinguish supported evidence, contradiction, low
  evidence, observational design, and unresolved intervals.

## Evaluation policy

`adclip bakeoff` is dry-run by default. Paid execution requires `--execute` and
normal live-API authorization.

The harness records:

```text
fixture
route
provider
model
options
latency
cost
artifact SHA-256
evaluation dimensions
human score / notes
```

Keep fixtures stable enough for longitudinal comparison. Add a fixture only when
it captures a materially different marketing failure mode.

## Runtime and billing policy

Runtime modes:

```text
online
restricted_network
offline
air_gapped
```

`ADCLIP_ALLOWED_NETWORK_PROVIDERS` controls external access in restricted mode.
Potentially paid generation requires `ADCLIP_ALLOW_LIVE_APIS=1`. Loopback text
inference is allowed offline/air-gapped; external endpoints are not.

Configuration:

```text
ADCLIP_TEXT_PROVIDER
ADCLIP_TEXT_MODEL
ADCLIP_IMAGE_ROUTE
ADCLIP_IMAGE_PROVIDER
ADCLIP_IMAGE_MODEL
ADCLIP_VIDEO_ROUTE
ADCLIP_VIDEO_PROVIDER
ADCLIP_VIDEO_MODEL
```

Meta read-only performance configuration includes:

```text
ADCLIP_META_ACCESS_TOKEN
ADCLIP_META_API_VERSION
ADCLIP_META_BASE_URL
ADCLIP_META_TIMEOUT
```

The generation-spend flag is not a generic network flag. Read-only performance
sync obeys runtime network policy but does not require paid-generation
authorization.

## Built-in providers

Text:

1. `claude-cli` — subscription-authenticated compatibility default.
2. `sampling` — sampling-capable MCP host.
3. `anthropic` — direct opt-in Anthropic API.
4. `openai-compatible` — local or hosted `/v1/chat/completions` endpoint.
5. `command` — local executable over stdin/stdout without a shell.
6. `fake` — deterministic tests/examples.

Media:

- fal image: GPT Image 2, Nano Banana, FLUX.2, legacy aliases, raw endpoints
- direct OpenAI image: Images API
- fal video: Kling, Veo, Seedance, Wan 2.7, Wan 2.6 legacy, raw endpoints
- fake image/video: deterministic tests/examples

Reference-image editing, vector generation, multi-reference video,
image-animation, and footage-edit routes are cataloged but intentionally
non-executable until their input contracts/adapters exist.

Legacy `LLM*` names and `llm_*` arguments remain compatibility aliases.

## Vendored declip slice

`src/adclip/_video_backend.py` supplies legacy fal aliases and loudness logic.
It is compatibility code, not the primary routing policy. Do not add `declip`
as a runtime dependency.

## Testing requirements

The unit suite must not require live paid models, a Meta account, or email sending.
Use fake providers and mocked HTTP.

Required media/provider coverage includes:

- provider/model independence and compatibility aliases;
- route recommendation and explicit overrides;
- unrelated model overrides not inheriting route-family options;
- unsupported route rejection;
- GPT Image, Nano Banana, FLUX, Kling, Veo, Seedance, Wan schemas;
- direct OpenAI image handling;
- offline/air-gapped provider policy;
- unused modalities not being resolved;
- invalid configured-route status reporting without crashing;
- route/provider/model provenance;
- dry-run bake-off making no provider call;
- CLI importing no module under `adclip.mcp`.

Required email coverage includes:

- HTML/text/footer/one-click headers;
- stable unique block IDs;
- structured and rendered-HTML patches targeting the same IDs;
- unsafe raw HTML and `javascript:` rejection;
- lint coverage for links/images/unsubscribe/active content;
- cadence from the brief rather than model invention;
- portable campaign export;
- fake-provider generation;
- no send provider/network dependency.

Required performance/experiment coverage includes:

- stable portable campaign identity;
- artifact changes producing new creative IDs;
- deployment snapshots preserving artifact hash;
- duplicate external Meta-ad relink guard;
- deterministic observation replacement on re-sync;
- GET-only Meta request construction and token non-persistence;
- account/ad identity verification;
- offline/air-gapped Meta sync blocking;
- attribution reporting time included in observation/window semantics;
- refusal to mix attribution modes silently;
- correct CTR/outbound CTR/action-rate denominators;
- reach remaining non-additive;
- observational experiments staying descriptive/inconclusive;
- minimum-evidence thresholds;
- supported/contradicted/inconclusive controlled rate examples;
- action events not exceeding binomial denominators for inference;
- CPA/ROAS remaining descriptive without variance evidence;
- `causal_claim: false` on current experiment evaluations;
- deterministic next-test action mapping;
- CLI/MCP registration for all learning tools.

Recommended local validation:

```bash
python -m pytest
python -m compileall src/adclip
python examples/build_performance_demo.py
```

## Current priority

The learning-loop foundation is now substantially implemented. Highest-value
next work is:

1. SQLite/migrations, global content-addressed artifacts, and durable resumable jobs;
2. BrandKit and SourceLibrary;
3. creative-attribute extraction plus experiment-aware controlled generation;
4. Google Ads, TikTok, and ESP performance connectors;
5. local browser workbench;
6. fatigue/change-point analysis and richer CPA/ROAS evidence;
7. separately authorized draft/paused activation.

Do not treat more generation modalities as automatically higher priority than
closing persistence, brand context, and learning-loop quality gaps.
